# BRIEF — mercurius-memory

Долговременная память агента на AMPHP и PostgreSQL с `pgvector`: факты с версиями, доверием и происхождением,
вспоминание фактов по ключам слов, однокоренным словам и векторам HRR, предложения изменений, которые решает
владелец, слой «всегда в контексте» и ночная проверка памяти кодом. Пакет — часть Меркурия
(`opencck/mercurius-memory`, пространство имён `Mercurius\Memory`), но в коде от приложения не зависит: только
`amphp/amp`, `amphp/postgres` и `wamania/php-stemmer`.

## Назначение и границы

В пакете:

- модель памяти: факт (`Fact`), предложение (`Proposal`), узкий интерфейс хранилища (`MemoryStore`) и журнал ночной
  проверки (`ConsolidationJournal`);
- разбор текста на ключи (стемы Snowball для русского и английского, стоп-слова, идентификаторы целиком,
  заимствования, однокоренные по словарю; китайский — упрощённое и традиционное письмо, слова по словарю jieba и пары
  иероглифов, `Chinese`), HRR, фильтр содержимого;
- сценарии: вспоминание (`Recall`), предложения и решения владельца (`Proposals`), правки слоя 1 по записям
  (`CoreEntries`), контекст запуска (`MemoryContext`), аудитория (`Audience`), подтверждение по дням
  (`Corroboration`), ночная проверка (`Consolidation`), таблица соответствий слов владельца (`Aliases`, `AliasStore`);
- хранилища PostgreSQL и в памяти, их SQL-миграции, контрактный тест хранилища, английские тексты.

В приложении остаётся:

- карточки владельцу «Принять»/«Отклонить» (`MemoryCards`) и доставка отчёта ночной проверки в чат;
- инструменты агента (`memory_search`, `memory_propose`, `memory_feedback` и др.) и команды `/memory`, `/forget`;
- подключение к агентскому циклу: слой 1 в системном промпте (`RunScheduler`), факты перед запуском, фоновый
  сборщик фактов `FactNudge`;
- поиск секретов для `ContentScreen` (`SecretMasker`), ключ отпечатков забытого (`MEMORY_SECRET`), часовой пояс и
  реплики участника для `Corroboration`;
- что происходит после «забыть»: вычистка текста из стенограмм, трасс, опыта и журнала проверки (слушатель
  `Proposals::onForget`);
- расписание ночной проверки, применение миграций, переводы текстов.

## Решения

- **Изменения памяти — только через владельца.** Агент предлагает, владелец решает; принятое пишется новой версией.
  Причина: факт возвращается в каждую следующую беседу.
- **Забытое не возвращается.** Факт удаляется с версиями и предложениями, остаётся только отпечаток HMAC его текста;
  ключ даёт приложение.
- **Фильтр до записи.** `ContentScreen` не пускает в память команды ассистенту, разметку ролей, секреты и невидимые
  символы: отравленный факт стал бы постоянной инструкцией. Текст читается и так, как выглядят его буквы-двойники
  (кириллица в латинском слове и наоборот, полноширинные буквы). Тот же фильтр `Recall` применяет на выходе, когда
  приложение его передало: факт, записанный при прежних правилах, проверяется нынешними.
- **Число, время и дата — слова, а не идентификаторы.** `TextAnalyzer::isPlainNumber`: они считаются в покрытии, но
  сами факт не вспоминают; сообщение из одного числа — о нём.
- **Изменённый факт говорит об этом.** `Recall::lines` дописывает «(обновлён дата)» 90 дней после смены текста;
  `Recall::format` — строки без пометки.
- **Относительный день получает дату при записи.** `RelativeDays` — «завтра (2026-11-28)» по дню, который даёт
  приложение (`Proposals`, замыкание `today`); без него текст остаётся как написан.
- **Качество поиска — в разборе слов, HRR только добавляет.** HRR — доля 0,3 в оценке факта, уже прошедшего гейт по
  словам; однокоренное слово весит 0,6 точного и само факт не вспоминает.
- **Эмбеддингов у внешних провайдеров нет.** Векторы HRR считаются у себя из SHA-256 слов; о словах ничего не хранится.
- **Аудитория по самому слабому слушателю.** Факты владельца — только владельцу в личном чате; в группе — только
  факты этого чата.
- **Ночная проверка — только код.** Модель не вызывается; ничего не меняется без владельца; ночь без изменений
  ничего не делает.
- **Тексты снаружи.** `Texts::translateWith` получает переводчик один раз при старте; без него — английский
  каталог. Пакет не зависит от `mercurius-i18n`.
- **Миграции нумеруются вместе с приложением.** Приложение применяет `Migrations::directory()` со своими по общей
  нумерации (`MigrationFolders`). Миграции ссылаются на таблицы приложения (`runs`, `principals`, `conversations`),
  поэтому отдельно от схемы Меркурия они не применяются.
- **Одно хранилище, один контракт.** `MemoryStoreContract` гоняется и на заглушке в памяти, и на PostgreSQL; новое
  хранилище обязано пройти тот же тест.
- **Образцы — holographic, dreaming и hermes.** Места указаны ссылками `ref:` в классах (версии фактов, поиск,
  фильтр, записи слоя 1, проверка памяти).

## Проверки

- `composer check` — PHPUnit (`AsyncTestCase`), PHPStan уровня `max` по `src` и `test`, Psalm `errorLevel="1"` с
  плагином PHPUnit. Тесты пакета работают без базы: анализатор, HRR, вспоминание, предложения, записи слоя 1,
  аудитория, фильтр, подтверждение и `InMemoryMemoryStore` через контракт.
- CI — GitHub Actions, одна задача: PHP 8.2, `composer install` и `composer check`; без сети и секретов, изменения
  только в `**.md` проверку не запускают, лимит 10 минут.
- Хранилище PostgreSQL проверяет приложение на настоящей базе: `PostgresMemoryStoreTest` наследует
  `MemoryStoreContract` (группа `integration`, на сервере проекта).
